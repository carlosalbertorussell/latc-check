# How often does the observed-domain trap occur naturally?

Generated by `python -I run_trap_frequency.py` (module `latc_check/trap_frequency.py`; Python 3.15.0, Windows-11-10.0.26100-SP0; seed 20210101; 20000 Monte Carlo draws per model and space; total 117.6 s).

**Trap**: a set of k example rows T0 misses at least one declared value of at least one attribute, so LATC's observed cardinalities are too small and every state with an unobserved value is missing. **Missing states** = |D| − ∏ m_i (m_i = observed values of attribute i); it is 0 without a trap.

## Method

* **Exact (uniform, without replacement)**: inclusion–exclusion over excluded value sets, P(no trap) = Σ (−1)^{Σ|S_i|} C(∏(d_i−|S_i|), k) / C(|D|, k), grouped by the sizes |S_i| and by attributes of equal domain size; integer arithmetic, one exact division. E[missing] = |D|·(1 − q), q = Σ_T (−1)^{|T|} C(∏_{i∈T}(d_i−1)∏_{i∉T}d_i, k) / C(|D|, k); E[missing | trap] = E[missing] / P(trap).
* **With replacement**: attributes become independent, P(no trap) = ∏_i Σ_j (−1)^j C(d_i, j)(1 − j/d_i)^k (coupon collector per attribute); the same product formula with Zipf probabilities gives the exact with-replacement Zipf value.
* **Rule of thumb**: union bound P(trap) ≤ Σ d_i (1 − 1/d_i)^k ≤ V·e^{−k/d_max} (V = Σ d_i), so k ≥ d_max·ln(V/α) rows suffice for P(trap) ≤ α.
* **Non-uniform (Monte Carlo, illustrative model only)**: *zipf_s1* — each attribute's value drawn independently with P(j-th declared value) ∝ 1/j, duplicate states rejected; *class_frequency* — rows of the real table drawn without replacement with weight ∝ the frequency of the row's class (typical outcomes are over-represented). Neither is a model of how any real expert writes examples; they only show the direction and size of the effect of skew. Each draw samples sequentially until every declared value is seen; trap(k) = [cover time > k].

Exact P(trap) at k = 17, 20, 30 identical (as fractions) across all 22 orders in every space: **True**. This is expected rather than a coincidence: changing the order only relabels the values within each attribute, and both the trap event (some declared value unseen) and the number of missing states are invariant under such relabelling, so the trap probability depends on each attribute's multiset of Zipf weights, not on which value receives which weight. The same holds without replacement, so the declared- and reversed-order Monte Carlo rows differ only by sampling noise (SE about √(p(1−p)/draws) ≤ 0.0035). What the order does change is *which* values tend to be missing (the last-ranked ones), not how often a trap occurs. The exact with-replacement figures differ from the without-replacement Monte Carlo ones by the with/without-replacement gap plus Monte Carlo noise.
