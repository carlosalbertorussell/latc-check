# Domain declarations of decision-table inputs in public DMN models

Generated by `run_dmn_corpus.py` (`latc_check/dmn_corpus.py`). Question: when a decision table's string inputs do not declare their allowed values, Drools skips gap analysis and observed-domain tools (dmn-js verifier) build the domain from the values the rules mention, so a value no rule mentions is never reported missing. How often do real, public DMN models declare those domains?

## Corpus

50 sources (shallow, sparse clones of public repositories, `.dmn` files only, at the commits listed under Sources; plus two analyser fixture sets from the earlier tool audit). 4191 `.dmn` files were found, 3725 distinct by SHA-256 of their bytes (duplicates dropped, by kind: {"analyser": 10, "product-test": 290, "other": 9, "example": 47, "tck": 110}; a file present in several places is kept once, in the kind of highest priority TCK > example > product test > analyser > other). 19 distinct files are not analysed (malformed XML, or not in a DMN model namespace; mostly deliberate negative test fixtures). 2882 decision tables were found in 1716 files.

Many tables recur in several files with different bytes (versions of the same TCK case, the same example copied into several example projects, Camunda 7 and its fork Operaton). The second set of numbers counts each distinct table content (hit policy, input expressions and typeRefs, every declaration text, every input and output entry) once: 1297 distinct tables.

Kinds: *examples / tutorials* = example, tutorial, demo and showcase repositories, and example folders of product repositories outside test folders; *product test resources* = test resources of engines, editors and libraries (Drools, Kogito, Camunda 7/8, Operaton, Flowable, dmn-js, jDMN, dsntk, ...); *conformance (TCK)* = the DMN TCK and TCK copies inside other repositories (`tck`, `TestCases`, `compliance-level-N`, `compatibility` folders); *analyser fixtures* = fixtures of verifiers / validators / linters (red6/dmn-check, Drools `kie-dmn-validation` tests, the dmn-js verifier fork, the Corea/Blatt/Delfmann verifier); *product, non-test* = remaining files of product repositories.

## Measures

Per decision-table input clause. *String input*: the inputExpression typeRef resolves, through itemDefinition chains, to `string`; inputs without a usable typeRef are typed from the variable they name, else from their entries (all string literals). *inputValues*: the input has a non-empty `inputValues`. *Reachable allowedValues*: an itemDefinition reachable from the inputExpression typeRef (directly or through a typeRef chain) or from the inputData / decision variable the expression names (also through itemComponents for `A.b` paths) has `allowedValues` (DMN 1.5 `typeConstraint` counts). *Usable by Drools*: `inputValues`, or `allowedValues` on the itemDefinition named by the inputExpression typeRef (the declarations Drools used for gap analysis in `results/drools/domains`; allowedValues reachable only through the inputData variable were ignored by Drools there, and a chain of several itemDefinitions was not tested, so neither is counted). *Declared value no rule mentions*: among inputs whose declaration is a list of string literals, some declared value appears in no input entry of the column (`not(...)` included): exactly a value an observed-domain tool cannot know. *No entry can match*: stronger; every entry of the column is a literal list or `not` of one, none is `-`, and none admits the value, so every state with that value is a gap, and an observed-domain tool misses all of them (columns with non-literal entries are left out of this ratio; counts in brackets).

## Exposure: single-hit tables an observed-domain tool cannot complete

A table is *exposed* when its hit policy is single-hit (UNIQUE, ANY, FIRST, PRIORITY; a missing hitPolicy is UNIQUE), it has a string input with no declaration (as above) whose entries mention at least one string literal, and no catch-all rule covers that column: no rule has `-` (or an empty entry) in that column and in every other input. A value no rule mentions then reaches no rule, and an observed-domain tool cannot report it. *Variant*: no rule has `-` in that column at all (a subset of the exposed tables). *Strict*: the exposed column's entries are all string literals, with no `-`, `not(...)` or other FEEL expression that could match a value the rules never name. Multi-hit tables (COLLECT, RULE ORDER, OUTPUT ORDER) are never exposed: an empty result is a legitimate answer for them. Denominator: tables with at least one string input.

### Sensitivity of the measures

* Default output: 28 of the 363 exposed tables (distinct contents: 23 of 190) have a defaultOutputEntry, so a value no rule mentions still gets a defined result; the exposure count does not read default outputs.
* Drools and typeRef: 15 of the 922 string inputs counted as usable by Drools have no inputExpression typeRef; Drools 7.74.1 then skips the table's gap analysis even with inputValues. Requiring a typeRef gives 907/2088 (43.4%) usable by Drools.
* Examples under test folders: files of example repositories keep the example kind even under a test folder. 30 of the 190 example tables sit under one (6 of the 34 exposed ones); without them, the 131 example string inputs declare a domain in 43.5% and in a form Drools uses in 36.6%.

## Caveats

* Selection bias: public repositories are dominated by engine test suites, conformance tests and small demos; production business models are rarely public. Test resources exercise features (often the declaration features themselves), so their declaration rates say little about business practice. The examples / tutorials row is the closest proxy, and it is small (171 files, 145 string inputs) and concentrated in a few repositories.
* Repositories were found from the candidate list, the `dmn` GitHub topic (repository search, not code search) and the repositories' READMEs; only each default branch's HEAD was taken.
* Duplicates are removed by bytes and, in the second table, by table content; near-duplicates with small edits remain.
* Typing is static: typeRefs naming imported models' types are not resolved (counted as `unknown`), and FEEL is not evaluated. A declaration that is not a list of string literals counts as declared but is left out of the unused-value measures.
* *Usable by Drools* follows the variants tested in `results/drools/domains`; other tools differ (the dmn-js verifier reads only the rules' values in any case).
