# Catala French family benefits (allocations familiales) as runnable Python

This folder holds a Python build of the Catala encoding of the French family
benefits (*allocations familiales*) and a script that re-runs the official
Catala tests through it. It is the executable ground truth planned for Paper C,
which tests whether the LATC algorithm can complete decision tables for a Rules
as Code model of legal texts.

**Result.** The official Catala tests pass under `clerk` (31 of 31 interpreted
checks, 15 of 15 test scopes through clerk's Python backend), and the
standalone Python re-run in `run_official_tests.py` passes (15 of 15 test
scopes, 18 assertions) on Python 3.12.3 and 3.13.16. The bundled Catala 1.3.0
runtime needs Python 3.12 or later, so Python 3.10 and 3.11 cannot run it (see
"Deviations").

## Contents

| Path | What it is |
|---|---|
| `generated/` | Python modules generated by Catala 1.3.0 for `Allocations_familiales`, `Prestations_familiales`, `Bmaf`, `Smic`, `France`, and the Catala French standard library modules they import (`*_fr.py`, `*_internal.py`). Unedited compiler output, apart from `__init__.py` (see below). |
| `runtime/catala/` | The Python runtime of the same Catala version (`runtimes/python/src/catala` at tag `1.3.0`): `catala_runtime.py`, `dates.py`. Standard library only. `runtime/pyproject.toml` and `runtime/README.md` are copied alongside for provenance. |
| `run_official_tests.py` | Re-runs every test scope of the two official test files through `generated/`. Standard library plus `runtime/` only. |
| `inputs.md` | Inputs of `PrestationsFamiliales` and `AllocationsFamiliales` (and the wrapper `InterfaceAllocationsFamiliales`), their declared types and enumeration values, and the statutory thresholds with their articles. |
| `clerk_test_results.txt` | Verbatim output of the `clerk test` runs, including the per-test JUnit XML report. |
| `LICENSE-catala-examples.txt` | Apache License 2.0 text from catala-examples (identical to the catala repository's `LICENSE.txt`). |

catala-examples' own `catala-examples.opam` and `Makefile` name Catala
`1.0.0~alpha`, a version label that predates the current release line.
Catala 1.3.0 is the current release and the first one published after the
inspected commit; it builds the commit and passes all of its tests, so no
other compiler version was tried.

The `Prestations_familiales.py` module comes from the separate
`prestations_familiales/` directory (scope `ÉligibilitéPrestationsFamiliales`),
which `Allocations_familiales` imports. The official tests use the scope
`PrestationsFamiliales` that `allocations_familiales/prologue.catala_fr`
declares inside the `Allocations_familiales` module; in Python that is
`generated.Allocations_familiales.prestations_familiales`.

## How to rebuild

```sh
# 1. Toolchain (Ubuntu 24.04, run as root in the container)
apt-get update && apt-get install -y opam ninja-build libgmp-dev pkg-config
export OPAMYES=1
opam init --disable-sandboxing --bare -n
opam switch create catala 4.14.2
eval $(opam env --switch=catala)
opam install catala.1.3.0          # about 10 minutes on 4 cores

# 2. Sources
git clone https://github.com/CatalaLang/catala-examples
cd catala-examples
git checkout 2694b17ddd7c2246e207e8f077d586349ee5abea

# 3. Official tests
clerk test allocations_familiales/tests/                    # interpreter: CLI tests + #[test] scopes
clerk test allocations_familiales/tests/ --backend=python   # #[test] scopes compiled to Python

# 4. Python backend (clerk target "allocations-familiales" from clerk.toml)
clerk build allocations-familiales
#    -> _targets/python/allocations-familiales/{Allocations_familiales,Bmaf,Prestations_familiales}.py
#    -> _targets/python/smic/{France,Smic}.py
#    -> _targets/python/libcatala/*_fr.py, *_internal.py, catala_runtime.py, dates.py

# 5. Assemble this folder
D=<this folder>
cp _targets/python/allocations-familiales/{Allocations_familiales,Bmaf,Prestations_familiales}.py $D/generated/
cp _targets/python/smic/{France,Smic}.py $D/generated/
cp _targets/python/libcatala/*_fr.py _targets/python/libcatala/*_internal.py $D/generated/
# runtime/catala/ = runtimes/python/src/catala from github.com/CatalaLang/catala at tag 1.3.0
```

`clerk build` was run without `--catala-opts=--trace`, so the generated code
carries no tracing hooks. The modules of `_targets/python/allocations-familiales`
are byte-identical to the copies clerk generated for the Python test run.

The generated modules import one another with `from . import X`, so they must
sit in one package. `clerk` writes three separate packages whose `__init__.py`
files contain `__all__ = [France, Smic]` and similar bare names; importing such
a package raises `NameError`. `generated/__init__.py` is therefore a one-line
package marker written for this folder; every other file in `generated/` is
unedited compiler output.

The 31 checks are:

  (`catala Typecheck`, `test-scope Test1` to `Test13`, and `Test13` a second

## Python re-run (`run_official_tests.py`)

```sh
python3 run_official_tests.py
```

The script puts `runtime/catala` on `sys.path`, imports `generated`, and runs
each test scope with the inputs and assertions of the Catala source:

* `tests_ouverture_droits.catala_fr` `Test1`: scope `PrestationsFamiliales` at
  2020-05-01 in Métropole, four assertions on `droit_ouvert` for four children;
* `tests_allocations_familiales.catala_fr` `Test1` to `Test14`: scope
  `InterfaceAllocationsFamiliales`, one assertion each on `i_montant_versé`.
  Conditions set with `règle ... rempli` are passed as `True`
  (`i_personne_charge_effective_permanente_est_parent` in every scope, plus
  `i_avait_enfant_à_charge_avant_1er_janvier_2012` in `Test12`); conditions the
  test leaves alone are passed as `False`, which is their Catala default.

Every scope of both files was translated; none was left out. Result on Python
3.13.16 (identical on 3.12.3):

```
PASS  tests_ouverture_droits.catala_fr  Test1  (4 assertion(s))
PASS  tests_allocations_familiales.catala_fr  Test1  (1 assertion(s))
...
PASS  tests_allocations_familiales.catala_fr  Test14  (1 assertion(s))

15 passed, 0 failed, 15 test scopes, 18 assertions checked
```

The exit status is 0 when everything passes and 1 otherwise. As a check that
the script can fail, a copy with `Test1`'s expected amount changed to
351,55 € and one `droit_ouvert` expectation inverted reported both as `FAIL`.

## Deviations and caveats

* **Python version.** The task asked for Python 3.10 or later. The Catala
  1.3.0 runtime uses PEP 695 generic syntax (`class Array[T: Value]`) and
  `typing.override`, both of which need Python 3.12. Under Python 3.11.17 the
  runtime fails to import with `SyntaxError: invalid syntax` at
  `catala_runtime.py` line 229; the script now checks the version first and
  stops with a message. Supported: Python 3.12 and later (tested 3.12.3 and
  3.13.16). The older PyPI `catala-runtime` 0.9.0 was left aside because it
  does not match the 1.3.0 compiler output.
* **Catala version.** The repository's opam file names `1.0.0~alpha`;
  1.3.0 was used, for the reason given under "Provenance".
* **Test count.** The two files contain 15 test scopes, with 16 CLI blocks
  and 31 clerk checks in all (detailed above).
* **Known behaviour of the encoding, kept as is.** Running the generated
  code outside the test dates shows that `Smic` raises a Catala `Conflict` for
  Mayotte between 2024-01-01 and 2024-10-31 (two overlapping SMIC
  definitions), and that the allocation forfaitaire is also paid for children
  already older than 20. Both are described in `inputs.md`. Enumerating the
  input space has to treat such runtime errors as outcomes of their own.
* **Valid dates.** `Smic` asserts `date_courante >= 2019-01-01` and `Bmaf`
  asserts `date_courante >= 2019-04-01`; earlier dates raise an assertion
  error.
