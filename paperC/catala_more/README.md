# Catala housing-benefit eligibility (APL) and US §121 as runnable Python

This folder holds a Python build of two more Catala encodings used as ground truth
in Paper C:

* the French housing benefits (*aides au logement*, module `Aides_logement`), whose
  scope `ÉligibilitéAidePersonnaliséeLogement` decides eligibility for the *aide
  personnalisée au logement* (APL);
* section 121 of the US Internal Revenue Code (module `Us_tax_code`, exclusion of
  gain from the sale of a principal residence).

It also holds scripts that re-run the official Catala tests through that build, and
the shared code used by the oracles of `paperC/specs/FR-APL/` and `paperC/specs/US-121/`.

**Result.** Every official test passes under `clerk` (Catala 1.3.0): 7 of 7 checks
for `tests_eligibilite_apl.catala_fr` (3 of 3 through clerk's Python backend), 67 of
67 for all of `aides_logement/tests/` (33 of 33 through the Python backend), and
18 of 18 for `us_tax_code/tests/`. The standalone Python re-runs pass 3 of 3
(`run_official_tests_apl.py`) and 6 of 6 (`run_official_tests_us121.py`) test scopes
on Python 3.13.16 and 3.12.3.

## How to rebuild

```sh
# 1. Toolchain (Ubuntu 24.04, as root in the container)
apt-get update && apt-get install -y opam ninja-build libgmp-dev pkg-config
export OPAMYES=1
opam init --disable-sandboxing --bare -n
opam switch create catala 4.14.2
eval $(opam env --switch=catala)
opam install catala.1.3.0          # about 10 minutes on 4 cores

# 2. Sources
git clone https://github.com/CatalaLang/catala-examples
cd catala-examples
git checkout 2694b17ddd7c2246e207e8f077d586349ee5abea

# 3. Official tests (interpreter, then clerk's Python backend)
clerk test aides_logement/tests/tests_eligibilite_apl.catala_fr --verbose
clerk test aides_logement/tests/tests_eligibilite_apl.catala_fr --backend=python --verbose
clerk test aides_logement/tests/ --verbose
clerk test aides_logement/tests/ --backend=python --verbose
clerk test us_tax_code/tests/ --verbose
clerk test us_tax_code/tests/ --backend=python --verbose   # runs nothing: see below

# 4. Python backend
clerk build aides-logement -b python                  # clerk.toml target "aides-logement"
#    -> _targets/python/aides-logement/Aides_logement.py
#    -> _targets/python/allocations-familiales/{Allocations_familiales,Bmaf,Prestations_familiales}.py
#    -> _targets/python/smic/{France,Smic}.py
#    -> _targets/python/libcatala/*_fr.py, *_en.py, *_internal.py, catala_runtime.py, dates.py
clerk build us_tax_code/python/Us_tax_code.py         # -> _build/us_tax_code/python/Us_tax_code.py

# 5. Assemble this folder
D=<this folder>
cp _targets/python/aides-logement/Aides_logement.py $D/generated/
cp _targets/python/allocations-familiales/{Allocations_familiales,Bmaf,Prestations_familiales}.py $D/generated/
cp _targets/python/smic/{France,Smic}.py $D/generated/
cp _build/us_tax_code/python/Us_tax_code.py $D/generated/
cp _targets/python/libcatala/*_fr.py _targets/python/libcatala/*_en.py _targets/python/libcatala/*_internal.py $D/generated/
# runtime/catala/ = runtimes/python/src/catala of github.com/CatalaLang/catala at tag 1.3.0
```

`clerk.toml` declares the target `us-tax-code` with `backends = ["ocaml"]` only, so
`clerk test us_tax_code/tests/ --backend=python` reports "NO TESTS WERE RUN" and
there is no clerk target to build. The module was therefore compiled with the
file-level clerk rule `clerk build us_tax_code/python/Us_tax_code.py` (same compiler,
default flags `-O`, as for the targets), and its official tests are re-run through
it by `run_official_tests_us121.py`. `Aides_logement.py` from `_targets` is
byte-identical to the copy clerk compiled for the Python test runs
(`_build/aides_logement/tests/python/*/Aides_logement.py`).

## Python re-runs

```sh
python3 run_official_tests_apl.py      # 3 passed, 0 failed, 3 test scopes, 3 assertions checked
python3 run_official_tests_us121.py    # 6 passed, 0 failed, 6 test scopes, 6 assertions checked
```

`tests_eligibilite_apl.catala_fr` has three test scopes: Exemple1 calls
`ÉligibilitéAidePersonnaliséeLogement` (APL) and asserts `éligible`; Exemple2 and
Exemple3 call `ÉligibilitéAllocationLogement` (allocation de logement) and assert
`AllocationLogementFamiliale`. All three are re-run. `test_section_121.catala_en` has
Test1–Test4 on `Section121SinglePerson` (`requirements_met`) and Test5–Test6 on
`Section121TwoPersons` (`income_excluded_from_gross_income`); all six are re-run.
`test_section_132.catala_en` concerns section 132 and is outside this work.

As a check that the scripts can fail: building Exemple1's household with every
input identical to the test is verified by structural equality of the Catala records
(`fr_apl_common.inputs_equal_exemple1`), and the interpreter cross-check below
includes a negative control.

## Interpreter cross-check of the ground truth

`interpreter_crosscheck.py` writes up to 600 sampled rows of each table (all rows of
FR-APL-1, US-121-1 and the non-excluded rows of US-121-2; EXCLUDED rows are not run)
as `#[test]` scopes of two Catala files placed in the catala-examples checkout, each
with the oracle's inputs and an assertion stating the ground-truth label. `clerk
test` then runs them with the Catala **interpreter**, so this check involves neither
the Python backend nor the Python input builders. A row agrees when its assertion
passes; a REJECTED row agrees when the scope fails with a run-time error (clerk
prints "During evaluation"; a failed assertion on a REJECTED row counts as a
disagreement). Result: see `interpreter_crosscheck_report.txt`
and the summary in `paperC/specs/README-FR2.md`.

Negative control: flipping the assertion of one FR-APL-3 row made the reader report
exactly that row as a disagreement ("Assertion failed").

## Known behaviour of the encodings, kept as is

These come out of the enumeration and are explained in each table's CONVERSION.md.

* `ÉligibilitéAidePersonnaliséeLogement` raises `NoValue` for every input before
  2019-09-01 (no `brut_horaire` of `Smic` before 2019-01-01; no definition of
  `personnes_à_charge_prises_en_compte` before 2019-09-01), and a `Conflict` in Mayotte
  from 2024-01-01 to 2024-10-31 (two `Smic` definitions overlap; the second one starts
  at 2024-01-01 where 2024-11-01 was meant).
* In Mayotte the encoding's surface rule and R844-4 are two exceptions to the same
  base rule and conflict when both apply.
* `Section121SinglePerson` raises a `DateError` whenever another §121 sale is given
  (`section_121.catala_en:376` compares a number of days with "2 year"), except for an
  earlier sale on the same day.
